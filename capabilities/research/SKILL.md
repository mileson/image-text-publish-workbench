# Bundled research capability

Run from the parent workbench when research is requested. This capability is included locally; no installation of the author's private research skill is required. Browser/search tools are supplied by the user's Agent, not by this repository.

1. Reuse the topic, audience, target platforms, existing materials and preferences already supplied. Ask only for missing decisions that prevent useful work. Define 3 research questions and a bounded sample target before searching; the default is 5 relevant posts per requested platform, not a popularity claim. Stop when the requested evidence is sufficient or access prevents progress.
2. Use the user's authorized browser/search tool. Prefer a task-owned existing browser session. Open original sources to verify claims. Do not use hidden credentials, bypass login challenges, or send private material to an external service without authorization. Paid searches require an explicit budget.
3. Collect title, accessible body, actual tags, date, source URL and retrieval time together. Missing fields remain null. Save permitted evidence files in the task output directory, outside this public repository. A search snippet is a discovery lead, not a verified full-text source.
4. Record the six metadata fields whenever available: created_at, updated_at, unique_visitors, visits, likes, comments. Add saves and followers when visible. Preserve raw displayed values and units. Unknown means null, never zero. Compare engagement only within the same platform and statistical scope.
5. Filter for topic relevance first; then weigh freshness, source authority and evidence quality. Prefer official sources for product facts. Separate observation, inference and proposed copy. Do not call a candidate keyword popular without traceable platform evidence.
6. Output research/sources.json using the local contract, research/findings.md with adopted ideas, rejected examples and gaps, and research/copy-patterns.md covering headlines, openings, explanations and tags. Write original drafts rather than copying other authors' prose.
7. For images, record source URLs, rights/use permission and intended role. An accessible image is not automatically licensed for republication. Use owned or licensed assets for redistribution. For location topics distinguish exact camera position from attraction/park coordinates; keep confidence and uncertainty explicit.
8. If a platform is blocked, mark that platform partial or unavailable, preserve the evidence already gathered, and use content-derived tags labeled as unverified. Continue the workbench from supplied materials when possible. Never mark a skipped search completed.

## Theme-driven image research

Choose source queries and sample size from the user's topic and output format, whether a product introduction, tutorial, travel note, educational card or other image/text task. No fixed pose, identity, location or 50-image quota is imposed. Gather only references that help the current topic, record what each will inform, and preserve source permission information.

## Optional gallery-reference mode

Use a gallery supplied by the user or a local folder they authorize. Inventory images, stable IDs, captions, rights and intended roles; inspect actual reference images. Let the user choose examples or use their delegated style choice. Extract transferable layout, typography, palette, composition and visual consistency, while replacing subject and copy with the current topic. A gallery is a style guide, not evidence for factual claims. No private gallery or portrait library is required.
